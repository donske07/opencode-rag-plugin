# OpenCode RAG Plugin

Local-first retrieval tools for [OpenCode](https://opencode.ai). The plugin indexes selected source files, documentation, and allowlisted web pages into PostgreSQL with pgvector, then retrieves relevant chunks with embeddings generated by a local GGUF model.

Retrieval is explicit: OpenCode calls `rag_search` when it needs indexed context. The plugin does not silently inject search results into every prompt.

## Features

- Local embeddings through `node-llama-cpp`
- PostgreSQL storage with pgvector and an HNSW cosine-distance index
- Token-aware chunks with configurable overlap
- Source-code, documentation, and bounded web ingestion
- Transactional per-source replacement with concurrent-writer serialization
- Repository-scoped chunks when multiple projects share one database
- Embedding model and dimension compatibility metadata
- File-size, response-size, redirect, timeout, and hostname boundaries
- OpenCode tools for indexing, search, and project-card storage

## Architecture

```text
files / docs / allowlisted web pages
                  |
                  v
       extraction and token chunks
                  |
                  v
       local GGUF embedding model
                  |
                  v
      PostgreSQL + pgvector HNSW
                  |
       rag_search embeds query
                  |
                  v
         nearest matching chunks
                  |
                  v
       OpenCode generates an answer
```

## Requirements

- Node.js 22 or newer
- OpenCode with local plugin support
- Docker, or an existing PostgreSQL 16 server with pgvector
- A local embedding GGUF compatible with the configured vector dimension

The embedding model is intentionally not included in this repository.

## Quick start

### 1. Install dependencies

```bash
npm ci
```

The approved install script is pinned to the declared `node-llama-cpp` version in `package.json`.

### 2. Start pgvector

```bash
docker compose up -d
```

The included Compose service binds PostgreSQL to `127.0.0.1:5432`.

### 3. Download an embedding model

```bash
mkdir -p models
curl --fail --location \
  "https://huggingface.co/ggml-org/bge-small-en-v1.5-Q8_0-GGUF/resolve/f2068edd9b54f2a369549ccc71f70ed273a2a801/bge-small-en-v1.5-q8_0.gguf" \
  -o "models/bge-small-en-v1.5-q8_0.gguf"
```

Review the model's upstream license and verify the downloaded artifact before use. Model weights remain excluded from Git.

### 4. Configure the process environment

```bash
cp .env.example .env
set -a
source .env
set +a
```

The plugin reads environment variables from the OpenCode process. It does not load `.env` automatically.

### 5. Register the plugin

For this checkout, copy `opencode.example.json` to `opencode.json`:

```bash
cp opencode.example.json opencode.json
```

From a different project, add the plugin source using an absolute file URL:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["file:///absolute/path/to/opencode-rag-plugin/src/index.ts"]
}
```

Quit and restart OpenCode after changing plugin configuration.

### 6. Index and search

Ask OpenCode to invoke the tools with structured arguments:

```json
{
  "tool": "rag_index",
  "arguments": {
    "files": true,
    "docs": true,
    "web": false,
    "confirm": true
  }
}
```

```json
{
  "tool": "rag_search",
  "arguments": {
    "query": "Where is web crawling restricted?",
    "topK": 5,
    "sourceTypes": ["files", "docs"]
  }
}
```

## Configuration

| Environment variable | Default | Purpose |
|---|---:|---|
| `RAG_POSTGRES_URL` | `postgres://localhost:5432/postgres` | PostgreSQL connection string |
| `RAG_EMBEDDING_MODEL` | `./models/bge-small-en-v1.5-q8_0.gguf` | Local GGUF path |
| `RAG_EMBEDDING_DIMENSIONS` | `384` | pgvector dimensions; must match the model and be at most 2,000 |
| `RAG_CHUNK_SIZE` | `500` | Maximum tokens per chunk |
| `RAG_CHUNK_OVERLAP` | `75` | Tokens retained between chunks |
| `RAG_SIMILARITY_THRESHOLD` | `0.3` | Maximum cosine distance; lower is closer |
| `RAG_MAX_FILE_BYTES` | `2097152` | Maximum bytes read from one local file |
| `RAG_FILE_ROOTS` | empty | Comma-separated source-code directories |
| `RAG_DOCS_ROOTS` | empty | Comma-separated documentation directories |
| `RAG_WEB_URLS` | empty | Comma-separated crawl start URLs |
| `RAG_WEB_ALLOWLIST` | empty | Required exact hostnames when web URLs are set |
| `RAG_WEB_MAX_PAGES` | `100` | Maximum successfully attempted pages |
| `RAG_WEB_REQUEST_TIMEOUT_MS` | `10000` | Timeout per HTTP request |
| `RAG_WEB_MAX_RESPONSE_BYTES` | `2097152` | Maximum bytes read from one web response |
| `RAG_WEB_MAX_REDIRECTS` | `3` | Maximum validated redirect hops |

Invalid numeric ranges, non-HTTP web URLs, overlap greater than or equal to chunk size, and web indexing without an explicit hostname allowlist are rejected at startup.

## Tools

### `rag_index`

Indexes enabled configured sources. `confirm` must be `true`.

- `files`: boolean, default `true`
- `docs`: boolean, default `true`
- `web`: boolean, default `true`
- `confirm`: boolean, default `false`

### `rag_search`

Embeds the query with the configured model and performs cosine-distance search.

- `query`: required string
- `topK`: integer from 1 through 20, default `5`
- `sourceTypes`: optional array containing `files`, `docs`, or `web`

### Project-card tools

- `project_card_save`: validates and stores a repository card in PostgreSQL and `.opencode/project-card.md`
- `project_card_get`: returns the local card, falling back to PostgreSQL
- `project_card_refresh`: refreshes the local card from PostgreSQL

The repository includes `/project-card` and `/code` command definitions under `.opencode/command`. Project cards are static command context and are separate from vector retrieval.

## Source boundaries

File indexing supports common source-code, markup, configuration, and text extensions. It skips hidden directories, dependency/build directories, model directories, common credential filenames, private-key formats, and files above `RAG_MAX_FILE_BYTES`.

Web indexing:

- accepts only HTTP and HTTPS URLs without embedded credentials
- requires exact hostname allowlisting
- revalidates every redirect and discovered link
- disables automatic redirects
- limits redirect hops, request duration, page count, and response bytes
- indexes HTML body text or plain text only

The allowlist is a host policy, not DNS pinning. Index only domains you trust.

## Storage behavior

Each source replacement runs in a transaction and takes a per-repository, per-source PostgreSQL advisory lock. Failed insertion preserves the previous chunks, and concurrent writers publish one complete replacement rather than a mixture. Searches are restricted to the repository identity supplied by OpenCode, preventing retrieval across projects that share a database.

The database records schema version, embedding dimensions, and the resolved model path. Changing model or dimensions, replacing model bytes at the same path, or opening an index created by an incompatible schema version requires dropping `rag_chunks` and `rag_index_metadata`, then rebuilding the index. Restart OpenCode after replacing model weights.

## Security and privacy

- Indexed text, metadata, embeddings, and project cards are plaintext in PostgreSQL.
- The project-card cache is plaintext on disk and is trusted only within the repository worktree.
- File exclusions reduce accidental secret ingestion but do not replace a dedicated secret scanner.
- Retrieved content is untrusted input to the active language model and may contain prompt-injection text.
- Use a dedicated local database role and database for this plugin.
- Do not point roots at home directories, credential stores, or unrelated workspaces.

See `SECURITY.md` for private vulnerability reporting.

## Known limitations

- Search is agent-invoked rather than automatically added to every prompt.
- There is no reranker after pgvector cosine-distance ordering.
- Deleted, moved, emptied, or no-longer-reachable sources are not automatically removed from the index.
- Existing chunks that later match a new exclusion remain stored until the index is cleared and rebuilt.
- Re-indexing is atomic per source, not across an entire multi-source run.
- Host allowlisting does not pin DNS answers.
- Chunk sizing uses `cl100k_base`, which can differ from the embedding model tokenizer.
